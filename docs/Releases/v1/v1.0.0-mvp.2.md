# OmniDesk v1.0.0-mvp.2

Release date: 2026-10-12
Status: Pre-release

## Summary

The second MVP release adds a neo-brutalist sci-fi HUD interface and fixes blocked login and Telegram loading on Windows. Provider message sending remains disabled.

## Added and Changed

- Redesigned login and workspace in dark and light modes with stronger contrast, readable message surfaces, responsive layouts, and clearer controls.
- Added provider connection diagrams and read/unread graphs based on the currently loaded view.
- Added a persistent motion control that respects system reduced-motion preferences.
- Bundled Space Grotesk locally with its font license and documented the product and design system.

## Fixed

- Authentication and security-check requests have deadlines and actionable retry messages instead of indefinite loading.
- Telegram reader processes enforce their timeout even without output and release their runtime lock afterward, preventing orphan readers from blocking the local backend.
- Background Telegram readers no longer prompt for phone numbers, codes, or passwords; session initialization has a 30-second deadline.
- Telegram discovery shares a 25-second budget across main, archive, and discovered folder lists. Available chats are retained with a visible notice when discovery times out.
- Telegram failures explain when to retry or reconnect without exposing credentials.

## Verification

- Frontend: 57 tests passed; lint and production build passed.
- Telegram adapter: 22 Python tests passed, including initialization deadlines and partial discovery results.
- Backend: all 120 tests passed (507 assertions), including 16 Telegram tests and silent-worker timeout/runtime-lock cleanup. Formatting passed, and all local database migrations are applied.
- Live development workspace: Telegram successfully loaded 120 chats after recovery. Gmail inbox loading was also observed during this work.
- Both themes, responsive layouts, contrast, and reduced motion were checked during the interface work.
- GitHub CI must pass before merge and publication.

## Upgrade and Rollback

- No database schema changes or new package dependencies are required.
- Restart the backend to terminate any old reader processes before using this version. Stop only processes belonging to this project.
- Local backend: `php artisan serve --host=127.0.0.1 --port=18001`.
- Local frontend: `http://localhost:5173`; configure `VITE_API_PROXY_TARGET=http://127.0.0.1:18001` for the development proxy.
- Existing Google OAuth, mail, Telegram application credentials, TDLib installation, and per-user sessions remain required.
- Roll back by checking out `v1.0.0-mvp.1` and rebuilding the frontend. No reverse migration is needed.

## Known Limitations

- This remains a pre-release and does not claim production readiness.
- Telegram discovery may return a partial loaded view when the time budget expires. Search and overview counts apply to loaded chats.
- Telegram and Gmail media availability depends on the provider and the connected account.
- Provider message sending, starred/custom label/settings views, and paid model services remain outside this MVP.
- This release does not establish production hosting, deployment, or full fresh-account end-to-end verification.
